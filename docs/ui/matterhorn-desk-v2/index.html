V2 Visual Redesign
7 Problems V2 Solves
These are the specific visual quality problems Codex must fix in the implementation.
P1
Too Many Outlined Boxes
Every card has border: 1px solid var(--border) — they stack as outlines competing for attention. V2: surface fills + subtle 1px separators.
P2
Monotonous Dark UI
Flat #0C0C0C everywhere with no warmth. V2: #111111 surface cards, per-desk accent tints, richer hierarchy.
P3
Profile/Wallet Hidden
Wallet address absent on desktop. V2: right rail profile card with truncated address + copy button.
P4
Side Rail = Info Dump
Every status, chip, and count crammed into the nav rail. V2: nav rail = clean icon+label; content in main + right rail.
P5
Fake Protocol Icons
Emoji (⚡💎📊) instead of SVG icons. V2: full SVG icon set per desk, currentColor, 24×24px, 1.5px stroke.
P6
Ugly Curved Session Cards
Heavy border-radius: 12px + nested card grids. V2: border-radius: 4px, no nested cards, metric chips not sub-cards.
P7
Bittensor Too Expert-Oriented
Raw Subtensor data, validator addresses, subnet IDs — developer dashboard. V2: beginner view by default, Expert toggle.
V2 Goal
Every problem above has a corresponding visual example on the next screens. Codex must verify each fix against the annotated examples before calling a desk done.

Do Not Build
Forbidden Patterns
These patterns must never appear in V2. Codex must catch them in visual review.
✕
Generic "Crypto workspace"
Never
Re-brands Matterhorn as a crypto app. Use protocol names.
✕
"Services" in customer nav
Never
Not a customer-facing desk in V1. Settings is the administrative hub.
✕
Seed phrase / private key input
Never — no exceptions
Matterhorn never asks for secrets. Public data only.
✕
API secret input field
Never for customer-facing features
Hyperliquid and Polymarket are preview-only. No credentials stored.
✕
"Submit order" / "Close position"
Never
Hyperliquid and Polymarket are preview-only in V1. External signer only.
✕
Medical diagnosis / prescription / treatment
Wellness: never
Wellness must use educational framing. No clinical claims. Sensitivity: Personal or Restricted only.
✕
Full wallet address (non-truncated)
Always truncate
Always 5CfTC…3bX9. Copy button provides full address.
✕
Emoji as primary protocol icon
Nav / desk icons: never
Use SVG icon system. Emoji acceptable in empty states only.
✕
Glassmorphism / blur panels
Explicitly forbidden
No backdrop-filter: blur(). No semi-transparent overlays.
✕
border-radius > 4px on data cards
Sharp corners standard
--v2-radius: 4px max. No curved corners on data cards.
✕
Nested card grids
Card contains content, not more bordered cards
A card holds text, chips, and inline metrics — not another card with its own border.
✕
Profile/wallet in bottom bar
Desktop: right rail. Mobile: top bar
Bottom bar has 5 desk tabs. Profile avatar is always in the top bar.
✕
Notification counts in left nav rail
Move to right rail bell
Nav rail = icon + tooltip. Bell with badge count lives in right rail.
✕
Computer Use in customer defaults
Developer-only feature
Not a default feature. Never appear in customer-facing desk defaults.
