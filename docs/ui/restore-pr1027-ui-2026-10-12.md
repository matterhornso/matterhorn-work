# Restore the PR 1027 interface

The user requests the pre-retro Matterhorn interface from PR #1027, merge `ad5b7298a1c53b4aff70ad9fd5b254ecaf4385ca`. This is an interface rollback on top of the tested source `f6a0e07b47f87237f4c79b27568b65f3f7e0a170`, not a destructive reset of later runtime, security, memory, accounting or authentication fixes.

## Direction contract

THESIS: Return to the existing PR #1027 layout and visual vocabulary; do not reinterpret it or introduce another redesign.

OWN-WORLD: Existing Matterhorn semantic colors, typography, rounded controls and subtle borders. No retro root marker, heavy outlines or block shadows by default. Respect saved light/dark preferences.

STORY: Users open their existing workspace, choose models, enter desks and access the earlier navigation and tools without migrating data.

FIRST VIEWPORT: Restore the incumbent workspace shell, sidebar, legacy workspace content and right tool rail at supported desktop widths. Mobile uses the existing responsive navigation and overlays. Model/profile/workspace access must remain available through existing supported paths.

FORM: User-pinned historical interface; no new direction roll or generated design comp. PR #1027 source and the retained flag-off UI are the reference. Keep later correctness, accessibility, consent and safety changes where they do not impose the rejected visual design.

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance

## Release behavior

Both `VITE_MATTERHORN_RETRO_UI` and `VITE_MATTERHORN_MINIMAL_UI` default off. Explicit `1` or `true` retains the optional preview; retro also enables the minimal layout. Existing deployments with either flag set must rebuild with both flags set to `0` to restore the legacy interface. No production configuration is changed by this branch.

The Docker web build, hydrated app, auth first paint and generated public guides must agree on the default. Guides added after #1027 remain available in incumbent styling; deleting their useful content is outside this visual rollback.

No data reset, migration, provider change, model call, approval bypass, force push, merge or deployment is part of this work. The current user preview stays unchanged; validation uses a separate frontend.
