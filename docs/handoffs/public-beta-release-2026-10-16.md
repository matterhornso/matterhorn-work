## Security update and compatibility checks

### 19 October operational changes

- The npm orchestrator installer and launcher require the matching platform package and refuse the unverified network/legacy `dist/bin` fallback. If optional dependencies were omitted, reinstall the exact package version with optional dependencies enabled; do not restore old fallback executables. Explicit operator binary-path overrides remain operator-controlled trust decisions, not verified downloads.
- Desktop preparation uses the existing pinned official OpenCode verifier, a private temporary directory and atomic replacement. It no longer executes an old sidecar to decide whether that file is trusted. Bun is required for the verifier; unsupported/custom repositories fail closed. Normal verified mirrors for the runtime sidecar path are a separate documented mechanism.
- Remote workspaces do not inherit the local managed OpenCode password. Path/dispose requests reject redirects. A remote service that requires authentication needs an explicitly supported credential binding; copying the local credential is not a workaround.
- Router and desktop HTTP failure responses use fixed public messages; arbitrary exceptions, local paths, parser snippets and adapter-start errors are not public diagnostics. Supported validation statuses remain available. Local diagnostics are bounded and do not include raw exception strings.
- Desktop control discovery tokens rotate through private staging and atomic `0600` file replacement. Existing leaf-link targets are not modified. Keep the user-data directory and its ancestors controlled by the desktop user; POSIX mode tests do not establish Windows ACL protection.
- Incoming attachments use independent generated storage identities and exclusive `0600` writes. Newly created directories request `0700`; existing attachments and directory permissions are preserved. Original sanitized filenames remain display metadata. Telegram credential-bearing download URLs are not attached to successful message metadata. This is not a claim that every third-party error/log path is redacted, nor a certification of hostile ancestors or Windows ACLs.
- Experimental Google account operations use a global local-owner connection, not a tenant-bound hosted account. Hosted sessions and non-owner clients must not use that connection. Mutating operations require writable mode and the existing approval service; operators must use the supported host approval queue. No Google connection is granted by this release. Ordinary five-desk chat remains independent of that optional integration.
- Skill-install approvals identify the exact requested owner/repository/ref and overwrite setting. Instructions and executable scripts still require source review. Existing symlink destinations are refused; file publication preserves existing hard-link targets. Mutable repository refs remain mutable source references, not reviewed content digests.
- Workspace restore drills default to a new private temporary directory, create owner-only exports/reports without overwriting existing files, and reserve the report before any approved restore. Retain the reported output directory securely. Secret-excluding exports can still contain private workspace content; they are not safe public evidence.
- Bittensor release evidence accepts only the structured readiness decision and exact supported receipt statuses. Narrative mentions, conflicting decisions, unsuccessful/prefixed statuses and unknown states do not establish readiness. This does not independently verify a receipt on chain.
- Generated-media readiness reports omit raw failure payloads. Browser-smoke reports use private evidence directories and bounded diagnostics instead of credential-bearing URLs and arbitrary exception text. Treat screenshots and reports as private even after this filtering. Legacy migration validation uses fresh private scratch directories and refuses failed signature checks; it is not part of the current web deployment procedure.
- Outputs-smoke cleanup accepts only the validated QA-session file and its correctly bound note, with responses from the configured app/backend origins. Failed or foreign responses do not become cleanup authority; authenticated backend calls refuse redirects. Smoke scripts remain operator tools, not permission to run them against production.

The canonical router unit command runs both Bun tests and the explicit Node attachment-race suite. Bun cannot rebind the named builtin filesystem exports needed by that fixture; keep the Node cases enabled rather than skipping the collision assertions. The CI contract enforces both paths.
