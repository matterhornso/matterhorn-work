# Phase 2 Implementation Plan

> **Date:** 2025-06-03
> **Status:** Draft — pending review

## Context

Phase 1 is complete. The bundle crisis is solved (308 → 11 chunks, 13.85 MB → 6.4 MB). Security tools are wired end-to-end. The MCP server is at v0.3.0.

Phase 2 should deliver **visible user value** — features that make the user feel the agent is genuinely useful, not just a research assistant.

## Goals

1. **Multi-step DeFi batching** — Agent proposes multi-step workflows (swap → approve → deposit) in a single transaction batch.
2. **Portfolio Tracker** — Aggregated view of positions across all protocols the user is exposed to.
3. **MEV-safe Routing** — Integrate CoW Protocol (MEV-protected swaps via batch auctions).
4. **Live Agent Session** — Agent can actually invoke tools during a chat session (not just show them in prompt).
5. **Hyperliquid End-to-End Live Test** — Test the full sign → submit flow with a real wallet.

## Trade-off: Phase 2 vs Phase 3

We're choosing depth over breadth:

- **Phase 2** = "The agent can actually DO things: batch transactions, show portfolio, protect from MEV."
- **Phase 3** = "New protocol integrations: Aave borrow, Uniswap LP, bridging, cross-chain."

We could do Phase 3 first, but users would still have to click Approve three times. Phase 2 makes every existing action smoother.

## Tasks

### Task 1: Multi-step DeFi Batcher (3-4 days)

**What:** Agent can propose multiple transactions that must happen in sequence:
- Swap ETH → USDC (1inch)
- Approve USDC for Aave (ERC-20 approve)
- Deposit USDC into Aave (supply)

**Where:**
- `apps/server/src/tools/defi-batcher.ts` — batch builder
- `apps/app/src/react-app/domains/wallet/TransactionApproval.tsx` — batch approval UI
- `apps/server/src/tools/approval-manager.ts` — already has `buildRevokeApprovalTx()`

**Design:**
- `buildBatch({ steps: [{ type: "swap", ... }, { type: "approve", ... }, { type: "supply", ... }] })`
- UI shows step-by-step breakdown: "Step 1/3: Swap ETH → USDC (~15 min gas)"
- Each step must succeed before the next is attempted
- If any step fails, show what failed and allow retry of remaining steps
- Security: total estimated cost in ETH + USD shown at top

### Task 2: Portfolio Tracker (2-3 days)

**What:** Show the user's complete on-chain position — ETH, USDC, LP positions, deposits in Aave/Morpho/Euler, open Hyperliquid perps.

**Where:**
- New page: `apps/app/src/react-app/domains/wallet/pages/PortfolioView.tsx`
- New server tool: `apps/server/src/tools/portfolio-tracker.ts`
- Data: viem readContract for token balances + DeFiLlama / Alchemy / DefiLlama

**Design:**
- Donut chart (recharts or custom CSS): asset allocation
- Cards per protocol: "Aave v3 — $1,234 USDC supply @ 5.2% APY"
- Hyperliquid section: open positions, margin used, PnL
- Table: all tokens with USD value, 24h change
- Security: read-only, no transactions

### Task 3: CoW Protocol MEV-Routing (1-2 days)

**What:** Replace 1inch with CoW Protocol for swap routing when MEV protection matters.

**Where:**
- `apps/server/src/tools/cow-swap.ts` — CoW API wrapper
- `apps/server/src/tools/swap-builder.ts` — optionally route through CoW

**Design:**
- `cow_getQuote({ chainId, sellToken, buyToken, sellAmount, from })`
- `cow_submitOrder(...)` — returns order ID for tracking
- UI: toggle "MEV Protection" in settings (default ON for mainnet)
- CoW orders are intent-based — no approve tx needed (GPv2VaultRelayer)

### Task 4: Live Agent Session Tool Invocation (2-3 days)

**What:** The agent doesn't just know about tools — it can actually call them during a session.

**Where:**
- `apps/app/src/react-app/shell/session-route.tsx` — add tool call handler
- `packages/matterhorn-work-crypto-mcp/index.mjs` — tool execution pipeline

**Design:**
- When agent proposes using a tool, show "🛠 agent is calling security_estimateGas..."
- Result shown inline in chat
- User can approve tool call before execution (opt-in for security)
- Error handling: "Tool call failed: rate limit on CoinGecko. Retrying in 30s..."

### Task 5: Hyperliquid End-to-End Live Test (1-2 days)

**What:** Test the full Hyperliquid trading flow with a real wallet on testnet.

**Where:**
- `apps/app/e2e/`
- `scripts/test-hyperliquid-e2e.ts` (already exists)

**Steps:**
1. Connect wallet (Base Sepolia)
2. Agent: "I want to long ETH perp"
3. Agent calls `hl_getFundingRates("ETH")`
4. Agent calls `hl_buildOrder({ asset: "ETH", isBuy: true, sz: 1 })`
5. UI shows approval modal with perp warnings
6. User clicks "Sign & Submit"
7. Wagmi signs EIP-712 typed data
8. Signature sent to server via hyperliquid SDK
9. Order submitted to `/exchange`
10. Agent calls `hl_getPositions` to confirm

**Success criteria:** One successful market order on Hyperliquid testnet with live signing.
