## Positioning

**Product name:** Matterhorn Work

**Tagline:** Your AI workspace for serious Web3 work

**One-line description:** Chat, research protocols, review wallet actions, and
keep notes, memory, and receipts together in one focused workspace.

**Short description:** Matterhorn Work turns complex Web3 work into clear,
reviewable flows. Use protocol desks for Bittensor, Hyperliquid, Polymarket, and
Sui; keep project context in Notes and explicit Memory; and inspect outputs and
receipts without handing private keys to an agent.

untracked files.

**Primary promise:** Matterhorn helps a user understand, prepare, review, and
record serious Web3 work. Signing stays in the user's wallet. Unsupported or
unproven integrations stay disabled and say `Coming soon`.

## Listing Copy

### Product Hunt description

Web3 work rarely lives in one place. Research is in a chat, wallet actions are
in a browser extension, project context is in notes, and receipts disappear
into folders.

Matterhorn Work brings those steps into one focused AI workspace. Start a
project chat, open a protocol desk, compare options, prepare a wallet action,
and keep the resulting notes, memory, files, and receipts attached to the same
project.

The safety boundary is simple: Matterhorn can explain and prepare actions, but
it never asks for seed phrases or private keys. Signing stays in your wallet,
memory is review-before-save, and integrations that have not passed acceptance
remain disabled.

The first public release focuses on Bittensor, Hyperliquid, Polymarket, and Sui,
plus the everyday project surfaces needed to keep the work understandable.

### Maker comment

We built Matterhorn Work because serious Web3 tasks were spread across chat,
wallets, dashboards, notes, and folders with no durable project trail.

Our goal is not to hide risk behind a magic button. Matterhorn makes the steps
clear: research, prepare, review, sign in your wallet, and keep the evidence.
Memory is explicit, unsupported integrations are quiet, and execution paths
fail closed.

We would especially value feedback on three things: whether the protocol desks
make complex workflows easier to understand, whether the wallet handoff is
clear enough before signing, and whether Notes, Memory, and Outputs make it
easier to return to a project later.

## Demo Script

Keep the launch demo under two minutes and use the final deployed app:

1. Open an existing project and ask a focused Web3 question.
2. Change Perspective once and show that the answer framing changes.
3. Open one protocol desk and run a public-read task.
4. Prepare a wallet action, stop at the external-wallet review boundary, and
   explain what Matterhorn cannot access.
5. Save one note, review one Memory suggestion, and open the resulting output.
6. End on the project trail rather than a settings or diagnostics screen.

## FAQ

**Does Matterhorn hold wallet keys?** No. It must never request or store seed
phrases, private keys, raw signatures, signed payloads, or wallet exports.

**Can an agent trade automatically?** No. Public agent, MCP, watch, and
background paths do not submit orders. A separately accepted connected-wallet
Hyperliquid flow can submit only after exact-term review and a fresh wallet
signature; keep it out of launch copy unless its final gate passes.

**What does Matterhorn remember?** Only items the user explicitly approves in
Memory. Notes are project content and are not silently promoted into memory.

**Which integrations are live?** Only integrations enabled in the final build
and named in its evidence packet. Disabled catalog entries say `Coming soon`.

**Is there a desktop app?** Publish the macOS link only when the exact release
assets are signed, notarized, stapled, Gatekeeper-accepted, and clean-install
tested.

**How do I report a problem?** Use Send feedback in the app or email
support@matterhorn.work without including credentials or signing material.
